## Why

Максим хочет уметь глобально отключать фискализацию (пробитие чека Evotor/Atol) для конкретной биржи прямо из каталога бирж (`/p2p-admin/`), не трогая код. Прецедент такого поведения уже есть, но зашит в код как разовое исключение — для биржи Intelion фискализация отключена жёстко (`if 'intelion' in exchange_type.lower(): SKIPPED`). Нужен тот же эффект, но управляемый кнопкой в админке для любой биржи из каталога.

## What Changes

- В каталоге бирж (`custom_admin/catalog.html`) у каждой биржи появляется кнопка-переключатель фискализации, рядом с уже существующими «Сделать публичной»/«Скрыть».
- Когда биржа отключена: чек не отправляется (`receipt.status="SKIPPED"`), сам ордер создаётся и сохраняется как обычно — оборот и прибыль считаются по нему наравне со всеми (подтверждено кодом: `_calc_currency_from_orders`/`export_excel_report`/админ-кэш прибыли не смотрят на `receipt`/`is_verified`).
- Реактивация — без автоматики: включение биржи обратно не допробивает задним числом ранее пропущенные ордера, это остаётся ручной операцией через админку, как и сейчас для прочих зависших чеков.

**Update (после первой реализации, по прямому решению Максима):** список пользователей-исключений («чек продолжает биться для отдельных юзеров, даже когда биржа отключена») убран полностью — «если чек не нужен, то он точно никому не нужен». Отключение биржи теперь безусловно для всех. Кнопка при этом стала иконкой-эмодзи 🧾, цвет которой сам показывает состояние (зелёный — чек включён, красный — отключён), вместо текстовой надписи «Отключить чек»/«Включить чек».

## Capabilities

### New Capabilities
- `exchange-receipt-toggle`: возможность администратора глобально включать/выключать отправку фискального чека для конкретной биржи из каталога.

### Modified Capabilities
(нет — специального формального описания текущего поведения фискализации по бирже раньше не было; это первая формальная спека на эту область, не изменение существующей)

## Impact

- `orders/models.py`: новое поле `Exchange.receipts_enabled` (bool, default `True`) — новая миграция. (M2M `receipt_exception_users` добавлялся и затем убран отдельной миграцией, см. Update выше.)
- `orders/receipt_service.py`: `create_or_update_and_send_receipt()` — новая проверка рядом с уже существующей проверкой Intelion, до похода в Evotor.
- `orders/views.py`: POST-диспетчер каталога (`custom_admin/catalog`) — новый `action` (по образцу `toggle_exchange_public`) для переключения `receipts_enabled`.
- `orders/templates/custom_admin/catalog.html`: новая кнопка-эмодзи рядом с существующими кнопками биржи.
- Единая точка проверки в `receipt_service.py` автоматически покрывает все три существующих пути отправки чека (расширение через `api_views.py`, ретраи верификации через `tasks.py`, ручная форма сайта через `views.py`) — эти файлы дополнительно не трогаем.
