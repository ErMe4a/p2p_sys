## Why

Максим хочет уметь глобально отключать фискализацию (пробитие чека Evotor/Atol) для конкретной биржи прямо из каталога бирж (`/p2p-admin/`), не трогая код. Прецедент такого поведения уже есть, но зашит в код как разовое исключение — для биржи Intelion фискализация отключена жёстко (`if 'intelion' in exchange_type.lower(): SKIPPED`). Нужен тот же эффект, но управляемый кнопкой в админке для любой биржи из каталога, плюс возможность оставить чек включённым для отдельных пользователей, даже когда биржа в целом отключена.

## What Changes

- В каталоге бирж (`custom_admin/catalog.html`) у каждой биржи появляется кнопка-переключатель фискализации («Отключить чек» / «Включить чек»), рядом с уже существующими «Сделать публичной»/«Скрыть».
- Когда биржа отключена: чек не отправляется (`receipt.status="SKIPPED"`), сам ордер создаётся и сохраняется как обычно — оборот и прибыль считаются по нему наравне со всеми (подтверждено кодом: `_calc_currency_from_orders`/`export_excel_report`/админ-кэш прибыли не смотрят на `receipt`/`is_verified`).
- Отдельный список пользователей-исключений на биржу — тем, кто в списке, чек продолжает биться, даже когда биржа глобально отключена. Это отдельный список от уже существующего «кому видна биржа» (`allowed_exchanges`), визуально показывается отдельным блоком, чтобы не перепутать с видимостью.
- Реактивация — без автоматики: включение биржи обратно не допробивает задним числом ранее пропущенные ордера, это остаётся ручной операцией через админку, как и сейчас для прочих зависших чеков.

## Capabilities

### New Capabilities
- `exchange-receipt-toggle`: возможность администратора глобально включать/выключать отправку фискального чека для конкретной биржи из каталога, с списком пользователей-исключений, для которых чек продолжает отправляться несмотря на отключение.

### Modified Capabilities
(нет — специального формального описания текущего поведения фискализации по бирже раньше не было; это первая формальная спека на эту область, не изменение существующей)

## Impact

- `orders/models.py`: новое поле `Exchange.receipts_enabled` (bool, default `True`) и M2M `Exchange.receipt_exception_users` — новая миграция.
- `orders/receipt_service.py`: `create_or_update_and_send_receipt()` — новая проверка рядом с уже существующей проверкой Intelion, до похода в Evotor.
- `orders/views.py`: POST-диспетчер каталога (`custom_admin/catalog`) — новый `action` (по образцу `toggle_exchange_public`) для переключения `receipts_enabled` и для добавления/удаления пользователя из списка исключений.
- `orders/templates/custom_admin/catalog.html`: новая кнопка + новый блок «Кому чек всё равно бить» под каждой биржей.
- Единая точка проверки в `receipt_service.py` автоматически покрывает все три существующих пути отправки чека (расширение через `api_views.py`, ретраи верификации через `tasks.py`, ручная форма сайта через `views.py`) — эти файлы дополнительно не трогаем.
