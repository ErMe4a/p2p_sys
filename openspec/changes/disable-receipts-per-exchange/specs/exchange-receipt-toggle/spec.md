## Purpose

Позволяет администратору глобально включать и выключать отправку фискального чека (Evotor/Atol) для конкретной биржи прямо из каталога бирж, с возможностью оставить чек включённым для отдельных пользователей-исключений.

## ADDED Requirements

### Requirement: Администратор может отключить чек для биржи
Система SHALL предоставлять администратору переключатель («Отключить чек» / «Включить чек») для каждой биржи в каталоге бирж, управляющий тем, отправляется ли фискальный чек по ордерам этой биржи.

#### Scenario: Администратор отключает чек для биржи
- **WHEN** администратор нажимает «Отключить чек» для биржи в каталоге
- **THEN** для этой биржи устанавливается признак «чек отключён», видимый в каталоге как «Включить чек»

#### Scenario: Администратор включает чек обратно
- **WHEN** администратор нажимает «Включить чек» для ранее отключённой биржи
- **THEN** признак «чек отключён» снимается, и новые ордера этой биржи снова получают чек в обычном порядке

### Requirement: Ордер с отключённым чеком сохраняется без фискализации
Когда чек для биржи ордера отключён и пользователь не входит в список исключений, система SHALL сохранить ордер как обычно (без ошибки) и SHALL не отправлять фискальный чек в Evotor/Atol.

#### Scenario: Ордер создаётся по отключённой бирже
- **WHEN** создаётся или верифицируется ордер с биржей, для которой чек отключён, и пользователь ордера не входит в список исключений этой биржи
- **THEN** ордер сохраняется со всеми полями как обычно, а его чек получает статус «пропущен» с указанием причины (отключено администратором для этой биржи)

#### Scenario: Проверка применяется независимо от пути отправки чека
- **WHEN** ордер по отключённой бирже поступает через любой из существующих путей отправки чека (создание через API, отложенная верификация, ручное редактирование на сайте)
- **THEN** во всех случаях чек одинаково пропускается по причине отключения биржи

### Requirement: Ордера с пропущенным чеком не отличаются в обороте и прибыли
Система SHALL учитывать ордера с пропущенным из-за отключения биржи чеком в обороте и расчёте прибыли пользователя наравне с ордерами, по которым чек был отправлен.

#### Scenario: Расчёт прибыли не зависит от статуса чека
- **WHEN** считается оборот или прибыль пользователя за период, в который входит ордер с пропущенным из-за отключения биржи чеком
- **THEN** этот ордер учитывается в расчёте так же, как учитывался бы при отправленном чеке

### Requirement: Список пользователей-исключений для отключённой биржи
Система SHALL позволять администратору указать для биржи с отключённым чеком отдельный список пользователей, для которых чек по-прежнему отправляется в обычном порядке, независимо от общего отключения биржи.

#### Scenario: Пользователь добавлен в список исключений отключённой биржи
- **WHEN** администратор добавляет пользователя в список исключений биржи, для которой чек отключён
- **THEN** новые ордера этого пользователя по этой бирже продолжают получать чек в обычном порядке

#### Scenario: Список исключений отделён от списка видимости биржи
- **WHEN** администратор просматривает биржу в каталоге
- **THEN** список пользователей-исключений по чеку показывается отдельно от существующего списка пользователей, которым видна биржа (видимость биржи и отключение чека — независимые настройки, не совпадают автоматически)

### Requirement: Повторное включение биржи не допробивает пропущенные чеки
Когда администратор включает чек для биржи обратно, система SHALL не отправлять задним числом чеки по ордерам, ранее пропущенным из-за отключения этой биржи.

#### Scenario: Включение биржи обратно
- **WHEN** администратор включает чек для ранее отключённой биржи
- **THEN** ордера, чек которых был пропущен во время отключения, остаются без чека до отдельного ручного действия администратора
