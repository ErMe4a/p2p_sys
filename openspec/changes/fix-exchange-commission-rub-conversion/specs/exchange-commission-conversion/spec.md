## Purpose

Зафиксировать единое правило перевода комиссии биржи (списывается в криптовалюте с каждой продажи) в рубли для
целей расчёта прибыли — одинаковое во всех местах системы, где прибыль считается или отображается.

## ADDED Requirements

### Requirement: Рублёвый эквивалент комиссии биржи считается по курсу каждой сделки

Комиссия биржи по каждой SELL-сделке переводится в рубли по курсу ЭТОЙ ЖЕ сделки (`комиссия_usdt × курс_сделки`),
и уже эти рублёвые суммы складываются для получения итогового вычета за период. Использование курса произвольной
другой сделки (например, последней в периоде) для перевода суммарной комиссии запрещено.

#### Scenario: Курс сделок в периоде отличается

- **GIVEN** у трейдера в периоде было 5 продаж с разными курсами (86.61, 89.76, 90.18, 91.38, 90.14) и ненулевой
  `exchange_commission_rate`
- **WHEN** считается рублёвый эквивалент комиссии биржи за период
- **THEN** результат равен сумме `комиссия_usdt_i × курс_i` по каждой из 5 сделок отдельно
- **AND** результат НЕ равен `(сумма комиссий_usdt по всем 5 сделкам) × курс последней из них`

#### Scenario: Все сделки периода по одному курсу

- **GIVEN** все SELL-сделки периода прошли по одинаковому курсу
- **WHEN** считается рублёвый эквивалент комиссии биржи
- **THEN** результат совпадает и при поэлементном расчёте, и при `сумма_комиссии_usdt × этот_курс` (частный случай,
  оба метода дают одно число — регрессия невозможна отличить только на этом случае, нужен пример с разными
  курсами)

### Requirement: Все места расчёта прибыли дают одинаковый рублёвый эквивалент комиссии биржи

Веб-страница «Прибыль» (`/profit/`, один пользователь/месяц), Excel-экспорт, админ-кэш годовой сводки и
админ-кэш помесячной сводки по всем пользователям — для одного и того же пользователя и периода должны показывать
одинаковую сумму рублёвого эквивалента комиссии биржи (в пределах округления до копеек).

#### Scenario: Сверка веб-страницы и Excel-экспорта

- **GIVEN** пользователь и месяц с несколькими SELL-сделками по разным курсам и ненулевой комиссией биржи
- **WHEN** открывается `/profit/` за этот месяц и параллельно выгружается Excel-отчёт за тот же период
- **THEN** сумма «Комиссия биржи, эквивалент в руб» из Excel (сумма новой колонки) совпадает с
  `month_exch_comm_rub` из `/profit/` с точностью до округления до копеек

#### Scenario: Сверка Excel-экспорта и админ-кэша

- **GIVEN** тот же пользователь и месяц, что и в предыдущем сценарии
- **WHEN** сравнивается сумма новой колонки в Excel с рублёвой комиссией, использованной при расчёте
  `MonthlyUserProfitCache`/`MonthlySystemProfitSummary` за тот же период
- **THEN** значения совпадают с точностью до округления до копеек

### Requirement: Excel-отчёт показывает комиссию биржи в рублях отдельной колонкой построчно

Итоговый Excel-файл содержит колонку «Комиссия биржи, эквивалент в руб» — для каждой строки продажи она равна
`Комиссия биржи (USDT) этой строки × Курс этой же строки`; для строк покупки и для строки переноса остатка —
всегда `0`. Итоговая формула «Прибыль» вычитает `SUM()` этой колонки, а не произведение суммы комиссии на курс
какой-либо одной сделки.

#### Scenario: Проверка построчного значения

- **GIVEN** строка продажи в Excel с Кол-во=X, Курс=Y, Комиссия биржи (USDT)=Z
- **WHEN** открывается ячейка колонки «Комиссия биржи, эквивалент в руб» этой строки
- **THEN** её значение равно `Z × Y`

#### Scenario: Строка покупки и строка переноса остатка

- **GIVEN** строка покупки (BUY) или строка "Перенос остатка"
- **WHEN** просматривается колонка «Комиссия биржи, эквивалент в руб» этой строки
- **THEN** значение равно `0`
