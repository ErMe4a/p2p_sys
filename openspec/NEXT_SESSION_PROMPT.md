## Сервер и деплой

- `ssh ubuntu@89.169.143.100`, проект `/opt/p2p_sys`, venv `venv/bin/activate`, sudo без пароля.
- Локально `.env` нет — любые реальные данные смотреть на сервере:
  `ssh ubuntu@89.169.143.100 "cd /opt/p2p_sys && source venv/bin/activate && python manage.py shell -c \"...\""`.
- Деплой только через git: коммит → `git push origin main` → на сервере `git pull` → `python manage.py migrate orders`
  (если есть миграции) → `sudo systemctl restart p2p` (+ `celery celery-sync celery-receipt celerybeat`, если
  затронут `tasks.py` или то, что он импортирует, например `receipt_service.py`).
- После деплоя: `curl http://127.0.0.1:8000/health`, `sudo journalctl -u p2p --since '2 minutes ago' | grep -i
  error`, и проверка страницы через `django.test.Client(SERVER_NAME='127.0.0.1')` + `force_login(...)`.
- Миграции генерировать локально (`makemigrations orders`) и коммитить вместе с кодом.

## Как работать

- Сначала разбирайся на реальных данных (read-only запросы на сервере), потом предлагай. Для аномалий прибыли/остатка
  сначала ищи один кривой ордер и сверяй с первоисточником (CSV биржи, банковская выписка, API биржи), только
  потом думай о структурных правках.
- Трейдера искать только точным `username=` (или по уникальному ключу вроде `receipt__contact`), никогда
  `icontains` + `.first()`.
- Если вопрос про бизнес-логику денег (что считать «грязной», когда списывать комиссию и т.п.) — разложи механизм
  с цифрами и спроси решение, не чини сам.
- Новая возможность → OpenSpec: `/openspec-explore` → `/openspec-propose` → `/openspec-apply-change`. Мелкие фиксы и
  баги — сразу кодом.
- Финансовые расчёты (LIFO, комиссия биржи в рублях) осознанно продублированы в трёх местах (Excel, `/profit/`,
  админ-кэш) — правь во всех трёх одинаково, не объединяй без явной просьбы.
- Каждую задачу фиксируй в `openspec/history.md` (новый подпункт §NN.x + общий итог в конце) и, если что-то
  осталось открытым или поменялся статус, в `openspec/project.md`. Не дублируй уже записанное.
- Коммиты: добавляй файлы поимённо, перед коммитом смотри `git status`/`git diff --cached`; `orders/management/`,
  `minin-p2p.zip`, `.scratch/`, `.claude/` не коммитить. Сообщение по-русски, объясняет «почему», в конце строки
  соавторства. После коммита — push и деплой, если это код.
- Расширение `minin-p2p/` — отдельный проект; перед правками сверяйся с `git log -- minin-p2p/` (бывало, что
  версия раздавалась zip-архивом без коммита). Текущая версия 1.5.7.
- Word-файлы (учёба) собирать через npm-пакет `docx`; LibreOffice/pandoc на этом ноуте нет — проверять только
  валидность XML и просить меня глянуть вёрстку в Word.

## Что нельзя

- Никогда не вызывать реальную отправку чека (`create_or_update_and_send_receipt`, Эвотор) на реальном
  пользователе без моего явного разрешения — даже «тестово», даже на 1 ₽. Откат транзакции БД не отменяет
  отправленный HTTP-запрос. Проверять логику — на условиях и временных записях, не на настоящих кассах.
- Не перезаписывать файлы на сервере поверх рабочего кода — только git pull.
- Не принимать пароли/коды через чат и не логиниться в боевые аккаунты бирж трейдеров. Для тестов расширения нужен
  отдельный тестовый аккаунт, вход в него делаю я сам.
- Не возвращать фолбэк «чек по непроверенным данным расширения».
